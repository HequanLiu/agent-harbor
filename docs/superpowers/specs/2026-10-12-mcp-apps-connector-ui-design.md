# MCP Apps 连接器 UI 解耦方案

日期：2026-10-12

状态：方案已确认方向，尚未实施。

基线：`feat/mes-connectors` 分支，`bdd9f7655284724bc513ce7c17b7365d4b0309e7`。

将业务界面从 Agent Harbor 迁移到连接器服务。连接器提供一套响应式 Web UI；Harbor 在浏览器、Tauri 桌面和移动端提供通用 MCP Apps 宿主。新增业务表单或修改业务字段，只发布连接器，不修改 Harbor 业务代码。

## 1. 目标和范围

- MES 连接器拥有订单摘要、订单编辑器、查询联动、资料识别入口及业务状态展示。
- Harbor 只承担连接器授权、UI 资源加载、隔离、消息桥接、生命周期和通用审批。
- 同一份连接器 HTML/CSS/JavaScript 构建产物覆盖桌面和手机；移动端不另写 MES 原生表单。
- 保留草稿保存、恢复、来源附件、AI 辅助填写、用户核对、正式提交和提交结果查询。
- 保留当前聊天协议；不要求整体切换为 AG-UI。
- 支持无 UI 能力的宿主返回文本结果。UI 加载失败不得导致工具被重新执行。
- 用第二个非 MES 连接器证明通用性，不能只以 MES 跑通作为解耦完成标准。

本方案不引入动态加载 Harbor React 模块的业务插件体系，不同时建设 A2UI 渲染器，也不把网页 UI 自动转换为各平台原生控件。连接器可以在自己的 UI 内使用 Schema 表单库。

MES 连接器服务端仓库为 `D:\WorkProject\mes.project\mes.clothes.mcp`，由用户指定，目录已确认存在。连接器工具、UI 资源及业务侧适配在该仓库实施；Harbor 通用宿主在 `D:\my-project\agent-harbor` 实施。现有 MCP 工具接口尚未核对，实施 MES 阶段前必须读取该仓库项目指令、检查分支和未提交改动并核对接口；不得将本文建议的新工具名视为已经存在。

## 3. 技术选择和职责

选择 MCP Apps。Schema/A2UI 可在已支持的控件范围内减少表单开发，但新增控件类型仍需要宿主适配；业务插件组件仍与 Harbor 发布耦合。MCP Apps 允许连接器交付独立 Web UI，更符合当前目标。

| 层 | 拥有的责任 | 不应承担的责任 |
| --- | --- | --- |
| 连接器服务 | MCP 工具、UI 资源、业务校验、权限、持久化和幂等 | 读取 Harbor 私有数据库 |
| 连接器 UI | 表单、摘要、业务交互、响应式布局、未保存状态 | 持有 Harbor Cookie、长期 OAuth 密钥 |
| Harbor 服务 | 用户与会话归属、授权代理、资源读取、调用关联、审批审计 | 判断 PO、BOM、订单状态含义 |
| Harbor 各端宿主 | 隔离容器、协议桥接、主题尺寸、展开关闭、能力协商 | 为每个业务实现控件和字段联动 |

采用官方 MCP Apps SDK 的宿主与 View 能力，不自行复制完整 JSON-RPC 协议。实施前锁定兼容的规范和 SDK 版本，以官方类型校验消息；不盲目更新现有 MCP 依赖。

## 4. 连接器协议

### 4.1 工具声明界面

以下为工具定义中的相关字段示例，完整工具仍需具有合法的 `inputSchema`：

```json
{
  "name": "mes_order_draft_create",
  "_meta": {
    "ui": {
      "resourceUri": "ui://mes/order-editor/v1"
    }
  }
}
```

连接器通过 `resources/read` 返回 UI HTML，媒体类型为 `text/html;profile=mcp-app`。建议将脚本和样式构建到资源内，减少外部依赖；需要外部资源时声明 CSP，由宿主校验并执行。

工具结果通过 `structuredContent` 提供草稿数据。Harbor 不解析其中的 `order`、`style`、`pos`、`bom` 等业务字段。文本 `content` 提供可独立理解的结果，供无 UI 宿主降级展示。仅供界面的结果元数据不得意外进入模型上下文。

### 4.2 工具和结果的可信关联

Harbor 在服务端记录工具调用对应的用户、租户、Agent、聊天会话、连接器实例、原始工具名、UI 资源和资源版本。浏览器不能通过传入 URL 或连接器 ID 改写归属。

保存工具定义的必要元数据、输入定义和可见性，分别构建模型工具列表与 UI 可调用工具列表。仅对 app 可见不等同于完成业务授权；每次调用仍检查授权和会话绑定。

保留结构化结果通道，审查 AgentScope 工具包装、事件序列化、历史持久化和前端消息恢复的完整链路，不能仅改工具发现接口或从 `getResultText()` 反向解析 JSON。

### 4.3 交互闭环

1. Agent 调用连接器工具；服务端保存调用来源和 UI 关联。
2. 前端根据可信关联创建通用 UI 会话。
3. Harbor 从对应连接器读取 UI 资源，建立隔离界面并完成初始化握手。
4. 宿主传递工具输入和结果；界面展示摘要或编辑器。
5. UI 通过桥接调用连接器工具；Harbor 重新校验权限并转发。
6. 连接器返回结果，由业务 UI 更新显示。
7. 关闭时执行资源清理；重新打开时读取最新业务数据。

UI 交互调用的结果按协议与产品策略更新聊天上下文，不将每次搜索或分页自动变成新的用户消息或模型运行。

## 5. Harbor 通用模块

拟新增模块：

| 文件 | 职责 |
| --- | --- |
| `apps/web/src/components/connector-ui/ConnectorApp.tsx` | 从可信调用关联进入 UI、加载和错误状态 |
| `apps/web/src/components/connector-ui/ConnectorAppFrame.tsx` | 隔离容器、AppBridge、初始化与销毁 |
| `apps/web/src/components/connector-ui/ConnectorAppDialog.tsx` | 展开、关闭、返回和未保存提示 |
| `apps/server/harbor/connectors/ui_api.py` | UI 会话生命周期与访问入口 |
| `apps/server/harbor/connectors/ui_bridge.py` | 限定资源和工具的代理 |
| `apps/server/harbor/connectors/ui_store.py` | UI 与原工具调用的持久关联 |
| `apps/server/harbor/connectors/approvals.py` | 通用审批挑战、决定、审计与凭据 |

移动端宿主放在 `apps/mobile` 的通用组件层，具体文件位置在读取该目录 `AGENTS.md` 并检查现有导航后确定。共享 Web 宿主逻辑提取为独立模块，避免直接依赖 Harbor Web 路由和页面组件。

拟定的内部 HTTP 接口：

| 接口 | 行为 |
| --- | --- |
| `POST /harbor/connector-ui/sessions` | 使用聊天会话与 `tool_call_id` 建立 UI 会话；服务端验证归属 |
| `POST /harbor/connector-ui/sessions/{id}/rpc` | 代理允许的 RPC 方法，限制大小、超时和目标 |
| `DELETE /harbor/connector-ui/sessions/{id}` | 失效 UI 会话并释放资源 |
| `POST /harbor/connector-ui/approvals/{id}/decision` | 从可信宿主审批界面接收用户决定 |

这些是 Harbor 内部接口，不要求其他宿主实现相同路径。加载隔离资源所需的内部入口同样绑定 UI 会话，不提供任意 URL 代理。

隔离遵循所选版本官方宿主模式。禁止直接把连接器 HTML 注入 Harbor DOM；禁止给业务 iframe 暴露原生 Tauri 或移动端任意调用桥。校验消息来源、实例和方法，实施 CSP、导航限制、资源大小及超时限制。连接器资源缓存按连接器身份和版本隔离，注销后清除私有缓存。

## 6. 一套 UI 覆盖多端

| 端 | 承载方式 | 端侧通用工作 |
| --- | --- | --- |
| 浏览器 | 隔离 iframe | 协议、主题、尺寸、弹窗、权限 |
| Tauri 桌面 | Web 前端中的隔离 iframe | 复用 Web 宿主，验证系统链接和文件能力 |
| 移动端 | WebView 承载可信宿主页，内部隔离业务 UI | 原生与宿主页桥接、返回、键盘、安全区、文件选择 |

同一资源 URI 和构建产物用于各端。连接器根据容器宽度提供桌面双列、手机单列布局；复杂明细在手机上可以显示为卡片。宿主传递支持的主题、语言、平台和尺寸信息。

移动 WebView 本身不自动满足 MCP Apps 隔离和通信要求，必须实现并验证完整宿主边界。原生桥只暴露给可信宿主页，由宿主页校验业务界面请求。

首期移动端点击聊天卡片后全屏打开 UI，避免在聊天列表内长期驻留多个 WebView。表单提供返回和未保存提示，并验证键盘弹起后提交按钮可见、旋转和后台恢复不会丢失已保存草稿。

新增业务表单无需修改宿主；新增扫码等平台能力可能需要新增通用能力并更新客户端。连接器必须检测能力，对缺少能力的宿主提供可理解的降级。

## 7. 草稿、文件和 AI 协作

### 7.1 草稿恢复和并发

连接器服务端是业务状态的唯一权威来源。保存携带版本，冲突时返回明确错误；UI 保留未保存输入，提示重新读取和人工合并。AI 更新或外部变更不得覆盖正在编辑的数据。

历史聊天保存原始调用关联和结果快照，重新打开 UI 时重新检查授权并读取当前草稿。资源不可用时展示文本快照，不重放创建或提交操作。

宿主关闭握手不能替代业务保存。未保存状态若需跨容器传递，使用显式协商的通用扩展；宿主不支持时由 UI 自身提供保存入口和退出提示。手机进程被杀不保证保留未保存字段，已保存草稿必须可恢复。

### 7.2 上传

由 MES 提供“申请上传”和“关联来源”工具：前者返回短时、限制大小和用途的上传地址，后者验证资产属于当前用户并关联草稿。现有 10 MiB 图片、20 MiB 来源文件限制和允许类型在连接器服务端执行。

Web UI 使用文件选择器上传，移动端宿主验证相册、文件及拍照支持。上传地址不得包含长期凭据，不进入聊天记录或模型上下文；其访问域需要满足宿主 CSP 和连接器 CORS 配置。失效时重新申请，不自动重试正式提交。

这是建议的连接器业务上传流程，不是 MCP Apps 内置上传 API。保留现有上传体验是迁移验收的一部分。

### 7.3 AI 辅助识别

将 MES 来源读取、草稿更新和证据核对指引从 Harbor `parse-source` 路由迁回 MES Skill 或工具流程。Harbor 只提供通用的消息提交与当前会话执行能力。

用户触发识别前由连接器验证来源已属于可编辑草稿。UI 发起的消息明确归属于当前会话，不得越权选择其他 Agent 会话；会话忙碌时显示重试提示。文件内容按数据处理，识别不得触发正式提交。

## 8. 通用审批与正式提交

MCP Apps UI 可见性不证明用户确认。当前 `X-Harbor-Bridge-Key` 保护必须保持到替代机制端到端通过，不能因界面迁移而放开普通工具直接提交。

新流程：连接器生成待执行操作和预览；Harbor 从连接器获取可信摘要，在宿主原生审批界面显示；用户确认后，服务端签发短时、单次使用的审批凭据，连接器验证后执行。

凭据至少绑定用户、租户、连接器、操作 ID、规范化参数摘要和有效期。Harbor 从服务端保存的挑战生成凭据，不接受 UI 自报“已确认”；连接器重新校验权限、草稿 revision 和 content hash。内容改变后旧凭据失效。凭据不交给模型，也不落入普通日志。

幂等和业务结果由连接器持久化。同一操作重复调用不重复录单；网络断开时显示状态未知并查询 operation，不能自动新建提交操作。

审批凭据是需协商的扩展，不是 MCP Apps 标准。信任配置按连接器实例建立，不按 MES 工具名硬编码。其他宿主不支持该扩展时，连接器提供自身的可信确认页面；必须经用户身份验证和单次操作确认后完成提交，再由 UI 查询结果。该路径必须独立验证，不依赖 Harbor 专用密钥。

## 10. 迁移、发布与回退

先发布具备新能力的连接器，再发布宿主；通过能力协商选择新 UI。过渡期旧版本连接器继续使用隔离的 legacy 入口，新功能不再增加到 legacy 路径。

旧订单链接由临时兼容模块转换为新 UI 入口，不能依赖扫描所有连接器猜测新调用的归属。既有历史消息缺少可信关联时，允许受控旧解析或只展示文本，并提示从当前已授权连接器重新打开。

阶段 B、C 通过前保留旧界面和确认保护；回退切换宿主入口，不回滚已保存业务数据，不重放提交。草稿模型采用兼容升级，UI 资源版本与数据版本分别管理。

清理旧路径的前提是历史恢复、各端交互和第二个连接器验收均通过。依赖 Harbor 审批扩展的连接器必须发布能力要求和降级方式。

## 11. 验证清单

| 类别 | 必须验证的场景 |
| --- | --- |
| 协议 | 能力协商、初始化、结构化结果、资源读取、工具可见性、超时、销毁 |
| 身份 | 不同用户同名工具、不同连接器同名资源、会话解绑、注销、授权撤销 |
| 隔离 | UI 无法访问宿主 Cookie/DOM/原生桥，伪造消息和任意地址代理被拒绝 |
| 表单 | 草稿创建保存、查询、明细联动、来源附件、AI 更新、版本冲突 |
| 恢复 | 历史聊天、旧链接、资源版本失效、断网重连、移动后台恢复 |
| 审批 | 无确认拒绝、取消拒绝、凭据过期、内容变化、重放、幂等、未知结果查询 |
| 多端 | 同一 UI 产物在 Web、Tauri 和真实手机完成操作 |
| 解耦 | 第二个连接器无需修改 Harbor 源码和业务路由即可接入 |

## 13. 2026-10-12 实施记录

当前在 Harbor `feat/mes-connectors` 和 MES `feat/order-mcp` 工作区实现核心迁移，尚未提交本轮改动。

- Harbor 使用官方 MCP Apps SDK 2.0.3 通用宿主，按真实工具调用关联打开 UI；后端协商标准 `extensions` 能力，保留结构化结果及历史绑定。
- Web/Tauri 共用 AppBridge，移动端使用同一桥接代码打包的可信 WebView shell。移动原生桥校验独立实例 nonce、UI session、当前登录和方法白名单；OAuth 凭据不进入 WebView。
- MES 在连接器仓库维护 React 表单，发布 `ui://mes/order-editor/v1`。订单字段、基础资料、草稿、图片/附件、识别请求和提交规则由连接器管理。
- 上传采用有界 MCP 分片，替代原设计的签名 HTTP URL：避免不同客户端额外处理上传凭据和跨域请求，代价是分片 RPC 开销及未完成上传不跨服务重启恢复。
- 新审批保存服务器生成的挑战，原生确认后一次性消费、签名执行；取消、参数替换及重复确认有测试。MES 复用现有持久化提交工作流。
- 包示例来自 `connector-meta.json` 的 `examples`，不再按 MES source 硬编码。旧 MES REST 路由隔离到 `legacy_mes.py`；旧前端入口保留用于迁移。

验证记录：Harbor 后端 246 通过、5 跳过；MES 完整测试 76 通过、3 跳过；Web 23 项测试与生产构建通过；移动端 25 项测试、TypeScript、Lint、Android JS 导出通过；Tauri Rust 1 项测试通过。最后补充的标准 RPC `_meta` 兼容由后端针对性 16 项回归覆盖。
